# PDF 편집기

## 요약

브라우저 안에서만 도는 개인용 PDF 편집기이며, 알PDF를 대체하려고 만들었다.
PDF를 서버에 올리지 않고, 모든 처리는 내 컴퓨터의 브라우저에서 한다.
쪽 정리(재정렬·삭제·회전·복제·병합·분할·추출), 주석, 양식 입력, 서명 이미지 넣기를 지원한다.
결과물은 HTML 파일 하나로도 만들 수 있다.
기본 엔진은 MuPDF이고, 설정에서 PDFium으로 바꿀 수 있다.

## 배경

PDF 편집기를 완전히 대체할 로컬 도구가 필요했고, 파일을 외부로 보내지 않는 것이 조건이었다.
사용자는 한 명이고 배포하지 않으므로, AGPL-3.0인 MuPDF를 쓰는 데 문제가 없다.
엔진은 어댑터 뒤에 두어서 UI가 어떤 엔진을 쓰는지 모르게 했다.

기본 엔진을 MuPDF로 정한 이유는 한글 때문이다.
MuPDF는 글꼴이 내장되지 않은 한글 문서를 설정 없이 그린다.
PDFium은 한글 글꼴 10~13MB를 따로 등록해야 하고, 한글 텍스트 상자와 한글 양식 값은 글꼴을 등록해도 안 그려지는 경우가 있었다.
측정 근거는 `docs/엔진결정.md`와 `harness/결과.md`에 있다.

## 사용법

### 준비

`app` 폴더에서 `npm install`을 한 번 실행한다.
시험에는 Node 24와 `qpdf`가 필요하다.
개발 서버(`npm run dev`)는 직접 실행해서 쓴다.

### 세 가지 빌드

모든 명령은 `app` 폴더에서 실행한다.

| 명령 | 결과 | 쓰임 |
|---|---|---|
| `npm run dev` | Vite 개발 서버 | 개발할 때 쓴다. 코드를 고치면 화면이 바로 바뀐다 |
| `npm run build:static` | `dist-static/` | 정적 파일 서버에 올려서 연다 |
| `npm run build:single` | `dist-single/index.html` | 파일 하나를 더블클릭해서 연다 |
| `npm run build` | 위의 두 결과물 모두 | 배포 전에 한 번에 만든다 |

`dist-static/`은 전체 15.6MB이고, 그중 15.1MB가 `engines/` 폴더의 WASM 파일 두 개다.
`dist-single/index.html`은 590,145바이트(약 576KB)다.
단일 HTML에는 코드와 워커만 들어 있고 WASM은 들어 있지 않다.

### 단일 HTML 첫 실행

단일 HTML은 처음 PDF를 열 때 엔진 파일을 내려받는다.
내려받기 전에 파일 크기와 이유를 화면에 보여 주고, `내려받기`를 눌러야 시작한다.

| 엔진 | 크기 | 내려받는 시점 |
|---|---|---|
| MuPDF | 약 10.4MB (화면에는 9.9 MB로 표시) | 기본 엔진으로 처음 열 때 |
| PDFium | 약 4.6MB | 설정에서 PDFium을 고르고 처음 열 때 |

내려받기는 다음 규칙을 따른다.

- 주소는 jsDelivr의 버전 고정 URL이다. MuPDF는 1.28.6, PDFium은 `@embedpdf/pdfium` 2.15.1이다.
- 받은 바이트의 SHA-256을 코드에 적어 둔 값과 비교하고, 같을 때만 저장한다.
- 해시가 다르면 저장하지 않고 오류 안내를 보여 준다.
- 저장 위치는 브라우저의 IndexedDB이고, 다음 실행부터는 저장본을 쓴다.
- 브라우저 저장소를 지우면 다시 내려받는다.

dev와 static 빌드는 같은 출처의 `engines/` 폴더에서 WASM을 읽고, 같은 IndexedDB 캐시를 쓴다.

### 엔진 선택

설정 서랍(오른쪽 위 톱니바퀴)의 `엔진`에서 고른다.
기본은 MuPDF다.
엔진을 바꿔도 이미 열려 있는 문서는 원래 엔진을 유지하고, 새로 여는 파일부터 새 엔진을 쓴다.
MuPDF 문서와 PDFium 문서 사이에서도 쪽을 보낼 수 있다.

### 기능

**보기**
- PDF를 창에 끌어다 놓거나 `파일 열기`로 연다. 확장자가 `.pdf`이거나 형식이 `application/pdf`이면 시도하고, 열리는지는 엔진이 판정한다.
- 화면에 보이는 쪽만 그리고, 벗어난 쪽의 비트맵은 버린다.
- 확대는 25%에서 400%까지다.
- 설정에서 테마를 시스템·라이트·다크 중에서 고른다.

**썸네일**
- 왼쪽 패널의 폭은 100~280px이고, 가장자리를 끌거나 설정 서랍의 슬라이더로 바꾼다.
- 썸네일마다 회전·복제·삭제 아이콘이 있다.
- 썸네일을 끌어서 순서를 바꾼다. 터치 기기에서는 손잡이를 끈다.
- 선택한 쪽을 다른 열린 파일의 탭 위에 놓으면 그 파일 끝에 복사한다.

**정리 모드**
- `G`나 툴바 버튼으로 보기 모드와 오간다.
- 왼쪽에 열린 파일 목록, 오른쪽에 썸네일 격자가 있다. 격자 썸네일은 80~320px로 조절한다.
- 클릭, Ctrl 클릭, Shift 클릭, 빈 곳에서 끌기로 쪽을 고른다.
- 쪽을 우클릭(터치는 길게 누르기)하면 복사·이동·복제·회전·삭제·추출·분할 메뉴가 뜬다.
- 쪽을 파일 목록의 파일 위에 놓으면 그 파일 끝에 복사하고, `새 파일` 칸에 놓으면 새 파일을 만든다.
- 쪽을 더블클릭하면 보기 모드로 돌아가 그 쪽을 연다.
- 정리 모드에는 본문이 없으므로 주석과 양식은 보기 모드에서 다룬다.

**다중 탭**
- 여러 PDF를 탭으로 동시에 열고, 최대 12개까지 연다.
- 탭마다 현재 쪽, 확대 배율, 선택한 쪽, 되돌리기 기록을 따로 보관한다.
- 같은 이름의 파일은 `이름 (2).pdf`처럼 구분한다.
- 저장하지 않은 변경이 있는 탭을 닫으면 확인 안내가 뜬다.

**쪽 조작**
- 재정렬, 삭제, 회전, 복제를 하고 되돌리기와 다시하기로 취소한다. 기록은 문서마다 20단계까지다.
- 선택한 쪽을 새 파일이나 열린 파일의 원하는 위치에 복사하거나 이동한다. 이동은 두 문서가 함께 되돌아간다.
- `열린 파일 병합`에서 파일을 체크하고 순서를 정하면 새 탭으로 합쳐진다. 원본 탭은 그대로다.
- 분할은 `1-3,5,8-`처럼 범위를 쓰거나 N쪽마다 나누고, 결과를 ZIP 하나로 받는다.
- 추출은 선택한 쪽만 든 PDF를 새로 받는다.

**주석**
- 하이라이트, 사각형, 원, 메모, 텍스트 상자를 넣는다.
- 만든 주석은 선택해서 이동하거나 크기를 바꾸고, 색, 글자 크기, 내용을 고치거나 지운다.
- 글자가 없는 쪽(스캔본)에서는 끈 영역을 하이라이트로 만든다.
- 주석은 PDF 표준 주석으로 저장한다.

**양식**
- 텍스트, 체크박스, 라디오, 콤보, 목록 칸을 채운다.
- `Tab`으로 다음 칸으로 간다.
- 읽기 전용 칸은 비활성이고, 서명 필드는 표식만 보인다.

**서명 이미지**
- PNG나 JPEG(20MB 이하)를 골라 쪽 위에 놓는다.
- 이미지는 표준 스탬프 주석으로 저장한다.

**저장**
- 원본을 덮어쓰지 않고 항상 새 파일로 내려받는다. 파일 이름은 `<원본>-편집.pdf`다.
- 저장 버튼 옆 화살표에서 옵션 세 가지를 고른다.

| 옵션 | 기본 | 동작 |
|---|---|---|
| 변경분만 덧붙여 저장 | 켜짐 | 원본 바이트를 그대로 두고 바뀐 부분만 뒤에 붙인다. 전자서명과 문서 정보가 유지된다 |
| 남은 데이터 정리 | 꺼짐 | 삭제한 쪽의 데이터를 지워 용량을 줄인다. 변경분만 덧붙여 저장과는 함께 쓸 수 없다 |
| 주석·양식을 내용에 굽기 | 꺼짐 | 주석과 양식 값을 쪽 내용에 합친다. 저장본에서는 다시 고칠 수 없다 |

### 단축키

설정 서랍에서도 같은 목록을 볼 수 있다.
글자를 입력하는 중에는 문자 키 단축키가 동작하지 않는다.

| 키 | 동작 |
|---|---|
| `Ctrl` `O` | 파일을 새 탭으로 연다 |
| `Ctrl` `S` | 새 파일로 저장한다 |
| `Ctrl` `Tab`, `Ctrl` `Shift` `Tab` | 다음 탭, 이전 탭으로 간다 |
| `Ctrl` `W` | 현재 탭을 닫는다 |
| `Ctrl` `Z` | 되돌린다 |
| `Ctrl` `Shift` `Z` | 다시 한다 (`Ctrl` `Y`도 같다) |
| `G` | 보기 모드와 정리 모드를 오간다 |
| `PageUp`, `PageDown` | 보기 모드에서 이전 쪽, 다음 쪽으로 간다 |
| `+`, `−` | 보기 모드에서 확대, 축소한다 |
| `Ctrl` 클릭 | 쪽 선택을 추가하거나 해제한다 |
| `Shift` 클릭 | 쪽 범위를 선택한다 |
| `Delete` | 선택한 주석이 있으면 주석을, 없으면 선택한 쪽을 지운다 |
| `Esc` | 선택 해제, 도구를 선택으로 되돌리기, 설정 닫기 |
| `V` | 선택 도구 |
| `H` | 하이라이트 |
| `R` | 사각형 |
| `O` | 원 |
| `N` | 메모 |
| `T` | 텍스트 상자 |
| `S` | 서명 이미지를 고르는 창을 연다 |
| `Tab` | 양식의 다음 칸으로 간다 |
| `Ctrl` `A` | 정리 모드에서 모든 쪽을 선택한다 |
| 방향키, `Home`, `End` | 정리 모드에서 칸을 옮긴다 |
| `Space`, `Enter` | 정리 모드에서 포커스한 쪽의 선택을 토글한다 |
| `Ctrl` + 휠 | 정리 모드에서 썸네일 크기를 바꾼다 |

하이라이트 도구는 쓴 뒤에도 켜져 있다.
사각형, 원, 메모, 텍스트 상자, 이미지 도구는 하나를 만들면 선택 도구로 돌아가고 방금 만든 주석이 선택된다.

### 시험

모든 명령은 `app` 폴더에서 실행한다.

```
node --test test/*.test.mjs
npm run check
```

- `node --test`는 어댑터, 저장 체인, 쪽 조작, 주석, 작업 공간, 바이너리 로더를 시험한다. 132개이고 약 18초 걸린다.
- 시험은 `qpdf`와 `python`을 부르고, 시험용 PDF는 `harness/samples/`에서 읽는다.
- 맑은 고딕(`C:/Windows/Fonts/malgun.ttf`)이 없으면 PDFium 한글 글꼴 등록 시험은 건너뛴다.
- `npm run check`는 `svelte-check`와 `tsc`를 차례로 실행한다.

브라우저에서 화면을 시험하는 스크립트는 저장소에 없다.

### 폴더 구조

```
pdf-edit/
├─ app/                  앱 소스
│  ├─ src/
│  │  ├─ App.svelte      첫 화면과 전역 키 처리
│  │  ├─ engine/         엔진 어댑터(MuPDF, PDFium), 워커, WASM 공급(BinarySource)
│  │  └─ lib/            화면 컴포넌트, 작업 공간 저장소(workspace), 되돌리기 기록, 쪽 범위, ZIP, 설정
│  ├─ test/              node --test 시험과 시험용 PDF 생성기
│  ├─ vite.config.ts     세 빌드 설정
│  ├─ dist-static/       build:static 결과물
│  └─ dist-single/       build:single 결과물
├─ docs/                 작업 지시서, 구현 계획, 엔진 결정, 다중 문서 설계, 마무리 점검
└─ harness/              엔진 비교 스크립트, 합성 샘플(samples/), 측정 결과(out/, out2/)
```

### 알려진 제한

- 암호가 걸린 PDF는 열 수 없고, 암호를 푼 파일을 열라는 안내만 나온다.
- PDFium을 고르면 글꼴이 내장되지 않은 한글 문서가 빈칸으로 보이고, 한글 텍스트 상자는 상자만 보인다. 한글 텍스트 상자를 만들면 앱이 한 번 안내한다.
- 선 도구가 없다. MuPDF 어댑터는 선과 펜 주석을 새로 만들지 못하고, 이미 있는 것을 읽고 옮기고 고치기만 한다.
- 변경분만 덧붙여 저장이 켜져 있으면 삭제한 쪽의 데이터가 파일에 남는다. 이때는 저장 직후 안내가 뜬다.
- 서명된 PDF를 변경분만 덧붙여 저장하면 서명 구간의 해시는 유지된다. 전체 저장이나 굽기 저장을 하면 서명이 무효가 된다.
- 서명된 PDF에 주석을 추가한 저장본을 서명 검증 도구(pyHanko)로 보면 서명 이후 변경으로 분류된다. Acrobat에서 어떻게 보이는지는 확인하지 못했다.
- 열 수 있는 파일은 12개까지다.
- 기존 본문 텍스트 수정, redaction(영구 삭제), 압축, PDF/A 변환은 없다.
- 최근 연 파일 목록은 없다.
- 합성 샘플로만 시험했고, 실제 업무 PDF로는 시험하지 않았다.
