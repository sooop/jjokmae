# PDF 도구 웹앱 작업 지시서

## 요약

브라우저에서 단독으로 도는 단일 HTML PDF 도구를 만든다. 페이지 조작과 주석·양식 입력이 중심이다. 엔진은 PDFium과 MuPDF가 후보이고 아직 하나로 정하지 않았다. 이번 작업은 두 엔진을 어댑터 뒤에 두고, 실제 PDF로 품질을 다시 확인한 뒤 기본 엔진을 정하는 것까지 포함한다.

바로 해야 할 일은 세 가지다.
- 프로젝트를 만들고 엔진 어댑터 틀을 세운다.
- 첨부한 비교 스크립트를 실제 사용 파일로 다시 돌려 기본 엔진을 정한다.
- 정한 엔진으로 뷰어, 썸네일, 페이지 조작, 저장을 구현한다.

## 배경

사용자는 PDF 편집기를 완전히 대체할 로컬 도구를 원한다. 서버에 파일을 올리지 않고, 본인 한 명이 개인 작업용으로 쓴다. 배포하지 않으므로 AGPL 라이선스 엔진도 쓸 수 있다.

## 개요

완성하면 사용자는 HTML 파일 하나를 더블클릭해 연다. PDF를 끌어다 놓으면 페이지 썸네일 패널과 본문 뷰어가 나타난다. 썸네일을 끌어 순서를 바꾸거나 삭제·회전하고, 여러 PDF를 병합하거나 나눌 수 있다. 하이라이트·도형·메모·텍스트 상자를 넣고, 양식을 채우고, 서명 이미지를 넣은 뒤 저장한다.

## 범위

포함하는 것

- 뷰어와 썸네일 패널
- 페이지 조작: 재정렬, 삭제, 회전, 병합, 분할, 추출
- 주석: 하이라이트, 도형, 메모, 텍스트 상자
- 양식 채우기와 서명 이미지 삽입
- 저장: 원본을 최대한 보존한다. 주석은 기본적으로 PDF 표준 주석으로 저장하고, 내보낼 때 평탄화(내용에 굽기) 옵션을 둔다.
- 엔진 교체가 가능한 구조

포함하지 않는 것

- 압축과 PDF/A 변환. 별도 프로젝트로 나눈다. Ghostscript 기반이므로 로컬 Node.js 서버를 쓰는 안을 사용자가 허용했다.
- 기존 본문 텍스트 수정과 redaction(영구 삭제). 사용자가 선택하지 않았다.
- 서버 업로드와 공개 배포.
- 수백 페이지 대용량 최적화. 요건에는 없지만 한 페이지씩 늦게 그리는 기본 구조는 처음부터 넣는다.

## 현재 상태: 이미 확인한 것

아래 수치는 Node 환경에서 합성 샘플 3종으로 잰 값이다. 샘플은 첨부한 `harness/samples`에 있다. 브라우저에서는 재지 않았고, 사용자의 실제 PDF로도 재지 않았다.

후보 엔진

| 엔진 | 버전 | 라이선스 | WASM 크기 |
|---|---|---|---|
| @embedpdf/pdfium | 2.15.1 | MIT (내부 PDFium은 Apache-2.0) | 4.6MB |
| mupdf | 1.28.6 | AGPL-3.0 | 10.4MB |
| pdfjs-dist | 6.5.438 | Apache-2.0 | 보조 WASM 0.1~0.5MB 여러 개 |
| pdf-lib | 1.17.1 | MIT | 없음 (렌더링 불가, 2022년 이후 갱신 없음) |

1페이지 렌더링 결과 (1.5배 확대)

| 샘플 | PDFium | PDF.js | MuPDF |
|---|---|---|---|
| 한글 임베디드 폰트 | 정상 | 정상 | 정상 |
| 한글 폰트 미내장 | 한글이 빈칸 | 한글이 빈칸 | 정상 |
| 스캔본 | 정상 | 정상 | 정상 |

- 한글 미내장 문서에서 PDFium WASM과 PDF.js는 한글을 그리지 못했다. PDFium WASM에는 시스템 폰트가 없다. PDF.js는 Node에서 쟀으므로 브라우저에서는 시스템 폰트를 쓸 수 있어 다를 수 있다.
- MuPDF는 내장 CJK 대체 폰트로 한글을 그렸다.
- 렌더링 속도는 세 엔진 모두 1페이지에 40~300ms였고 큰 차이가 없었다.

저장 결과 (첫 페이지 90도 회전, 마지막 페이지 삭제)

- PDFium, MuPDF, pdf-lib 모두 qpdf 검증을 통과했고 페이지 수와 회전이 맞았다.
- 삭제한 페이지의 객체가 남는 정도가 달랐다. 스캔본 2페이지 중 1페이지를 지웠을 때 PDFium은 1.14MB에서 0.56MB로 줄었다. MuPDF와 pdf-lib는 1.14MB 그대로였다. MuPDF는 저장할 때 가비지 컬렉션 옵션이 필요하다.

측정하지 않은 것: 주석과 양식 저장, 증분 저장 보존, 전자서명 유지, 암호화 파일, 대용량 파일, 브라우저 환경의 PDF.js 폰트 처리.

## 방침

### 엔진은 어댑터 뒤에 둔다

렌더러와 편집기를 하나의 인터페이스로 감싸고 PDFium 어댑터와 MuPDF 어댑터를 모두 만든다. UI는 어댑터 인터페이스만 안다. 인터페이스에 최소한 다음 동작이 들어간다.

- 문서 열기와 닫기, 페이지 수, 페이지 크기
- 페이지를 비트맵으로 그리기 (확대 배율 지정)
- 페이지 회전, 삭제, 이동, 다른 문서에서 가져오기
- 주석 읽기·추가·수정·삭제, 양식 필드 읽기와 값 쓰기
- 저장 (바이트 배열 반환, 증분 저장과 전체 저장 선택)

PDF.js는 렌더링 비교용으로만 두고 편집 어댑터는 만들지 않는다. pdf-lib는 어댑터가 막힐 때 병합·분할용 보조로만 쓴다.

### 기본 엔진은 실제 파일로 정한다

첨부한 `harness`를 사용자의 실제 PDF(한글 문서, 폰트 미내장 문서, 스캔본)로 다시 돌려 결과를 사용자에게 보여 주고 정한다. 판단 기준은 다음이다.

- MuPDF가 한글 미내장 문서를 올바르게 그리면 MuPDF를 기본으로 하는 쪽이 유리하다.
- PDFium을 기본으로 하려면 한글 폰트를 직접 등록하는 방법이 동작해야 한다. PDFium의 폰트 등록 API(`FPDF_AddInstalledFont`, `FPDF_SetSystemFontInfo`)로 한글 폰트를 붙일 수 있는지 먼저 확인한다. 폰트 크기는 Noto Sans KR 부분 집합 기준 수 MB로 예상한다.
- 주석과 양식 저장은 두 엔진 모두 실제로 해 보고 비교한다. 이 비교가 기본 엔진 결정에 영향을 준다.

### 단일 HTML과 WASM 내려받기

- 개발은 Svelte와 Vite로 하고, 마지막에 `vite-plugin-singlefile` 같은 방법으로 단일 HTML을 빌드한다.
- JS 코드와 워커 코드는 HTML에 인라인한다. WASM과 한글 폰트 같은 큰 바이너리는 필요한 시점에 CDN(jsDelivr)에서 내려받아 IndexedDB에 저장하고, 이후에는 저장본을 쓴다. 사용자가 이 방식을 허용했다.
- 버전을 고정한 URL만 쓴다. 내려받은 바이트의 해시를 코드에 적어 두고 일치할 때만 저장한다.
- PDFium은 `init({ wasmBinary })`로 바이트를 직접 넘길 수 있다. MuPDF가 WASM 바이트를 외부에서 받을 수 있는지는 확인하지 못했다. 안 되면 대안을 찾아 사용자에게 알린다.
- 처음 한 번은 네트워크가 필요하다는 점이 오프라인 사용에 영향을 주므로, 내려받기 전에 사용자에게 크기와 이유를 한 줄로 보여 준다.
- `file://`로 열었을 때 워커, IndexedDB, CDN 요청이 모두 동작하는지 초기에 확인한다.

### 메모리와 속도

- 엔진은 Web Worker 안에서 돌린다. 메인 스레드는 UI만 맡는다.
- 썸네일과 본문은 화면에 보이는 페이지만 그리고, 안 보이는 페이지의 비트맵은 버린다.
- 큰 파일은 `ArrayBuffer`를 복사하지 않고 transfer로 넘긴다.

### 저장 원칙

- 원본을 덮어쓰지 않는다. 항상 새 파일로 내려받는다.
- 증분 저장(변경분만 덧붙이기)을 기본으로 시도해 기존 전자서명과 메타데이터를 보존한다. 엔진이 지원하지 않으면 전체 저장으로 내려가되 사용자에게 한 번 알린다.
- 페이지를 삭제했을 때 남는 객체는 정리하는 옵션을 둔다.

## 화면 규칙

반복해서 쓰는 도구이므로 아래를 처음부터 적용한다.

- 색상 테마는 만들기 전에 사용자에게 한 번 묻는다. 후보는 모노톤, 오프화이트+오렌지, 크림+모노카이다. 다크 모드를 함께 지원한다.
- 글꼴은 Pretendard Variable, Pretendard 순으로 선언하고, 고정폭은 Geist Mono를 앞에 둔다. 웹폰트 링크는 넣지 않는다.
- 모서리 반경이 있는 요소에 한쪽 변만 굵은 색 테두리를 주지 않는다.
- 자명한 안내 문구와 푸터를 넣지 않는다. 설명이 필요하면 호버 설명으로 둔다.
- 첫 화면은 빈 상태다. 예시 PDF를 미리 넣지 않는다.
- 파일 열기 버튼과 함께, 뷰어 영역 전체를 드롭 영역으로 만든다. 확장자 `.pdf` 또는 MIME `application/pdf` 중 하나만 맞으면 열고, 최종 판정은 엔진이 문서를 여는 데 성공했는지로 한다. 여러 파일을 놓으면 모두 탭으로 연다. (2026-11-12 변경: 병합 대기 목록 폐지, 상세는 `다중문서설계.md`)
- 썸네일 패널의 작은 버튼(회전, 삭제, 복사)은 아이콘으로 만들고 `aria-label`과 `title`을 붙인다. 터치 대상은 28px 이상이다.
- 가끔 쓰는 기능(설정, 단축키 안내)은 오른쪽 서랍 패널에 둔다.
- 설정(마지막에 쓴 엔진, 확대 배율, 평탄화 옵션, 테마)은 localStorage에 마지막 값만 저장하고, 접근은 모두 `try/catch`로 감싼다.
- 입력 필드 글꼴은 터치 기기에서 16px 이상으로 한다.
- 최근 연 파일 목록은 만들지 않는다. PDF 바이트를 저장소에 쌓는 일은 용량 부담이 크다. 필요하다고 사용자가 요청하면 파일 이름과 열어 본 페이지만 저장한다.

## 작업

각 작업의 완료 기준을 함께 적는다. 담당은 모두 Claude Code다.

| 작업 | 완료 기준 |
|---|---|
| 프로젝트 설정: Svelte, Vite, 단일 HTML 빌드, 어댑터 인터페이스 정의 | 빈 화면이 단일 HTML로 빌드되고 `file://`에서 열린다 |
| WASM 로더: CDN 내려받기, 해시 확인, IndexedDB 저장, 진행 상태 표시 | 두 번째 실행부터 네트워크 없이 엔진이 뜬다. 해시가 다르면 저장하지 않고 오류를 보여 준다 |
| 엔진 품질 재측정: 첨부 하네스를 실제 PDF로 실행하고, 한글 폰트 등록과 주석·양식 저장을 추가로 측정 | 결과 표를 사용자에게 보여 주고 기본 엔진 결정을 받는다 |
| 어댑터 구현: PDFium, MuPDF | 같은 시험 PDF에서 두 어댑터가 같은 인터페이스로 열기, 그리기, 회전, 삭제, 저장을 수행한다 |
| 뷰어와 썸네일: 보이는 페이지만 그리기, 확대·축소, 페이지 이동 | 300페이지 PDF에서 스크롤이 끊기지 않는다 |
| 페이지 조작: 드래그 재정렬, 삭제, 회전, 병합, 분할, 추출 | 조작 후 저장한 PDF가 qpdf 검사를 통과하고 Acrobat과 브라우저 기본 뷰어에서 같은 내용으로 열린다 |
| 주석: 하이라이트, 도형, 메모, 텍스트 상자 | 저장한 PDF를 다른 뷰어에서 열어 주석을 다시 편집할 수 있다 |
| 양식과 서명: 필드 채우기, 서명 이미지 배치 | 채운 값이 다른 뷰어에서도 보인다 |
| 저장 옵션: 증분 저장, 평탄화, 남은 객체 정리 | 서명된 시험 PDF를 증분 저장해도 서명이 유지되는지 확인한 결과를 보고한다 |
| 마무리 점검 | 아래 성공 기준을 모두 확인하고 확인하지 못한 항목을 보고한다 |

## 성공 기준

- 단일 HTML 파일을 더블클릭해 열고, 페이지 정리(재정렬, 삭제, 병합, 분할)와 주석 저장이 끝까지 된다.
- 저장한 PDF가 Acrobat과 브라우저 기본 뷰어에서 깨지지 않고, 표준 주석은 다시 편집할 수 있다.
- 한글 임베디드·미내장·스캔본 샘플에서 엔진별 렌더링과 저장 품질을 확인했고, 기본 엔진을 정한 근거가 문서로 남았다.

## 미정 사항

| 항목 | 정할 사람 | 기본값 |
|---|---|---|
| 기본 엔진 (PDFium 또는 MuPDF) | 사용자 | 재측정 결과를 보고 정한다. 그때까지 두 어댑터를 모두 만든다 |
| 실제 PDF 샘플 | 사용자가 준비 | 없으면 첨부한 합성 샘플로 진행한다 |
| 한글 폰트를 번들에 넣을지 | 사용자 | PDFium을 기본으로 하는 경우에만 검토한다. CDN에서 내려받아 IndexedDB에 저장한다 |
| 압축·변환 별도 프로젝트 시작 시점 | 사용자 | 이 프로젝트에서는 만들지 않는다 |
| 브라우저에서의 PDF.js 한글 폰트 처리 | Claude Code | 재측정 때 실제 브라우저에서 한 번 확인한다 |
| 테마 | 사용자 | 만들기 전에 질문한다 |

## 유의할 위험

- 단일 HTML에 JS와 워커만 인라인해도 크기가 커진다. 빌드 결과 크기를 확인한다.
- `file://` 환경에서는 워커 생성과 CDN 요청이 제한될 수 있다. 가장 먼저 확인한다.
- pdf-lib는 일부 암호화·손상 파일을 열지 못하고 저장할 때 일부 메타데이터와 서명이 사라질 수 있다. 어댑터의 주 경로로 쓰지 않는다.
- 엔진마다 한글 폰트 대체 결과가 달라 같은 문서가 다르게 보일 수 있다. 화면 표시와 저장 결과가 다른 경우를 구분해서 보고한다.
- 주석과 양식은 이번 측정에 없다. 엔진 결정은 이 측정이 끝난 뒤 최종 확정한다.

## 첨부 자료

`harness` 폴더에 비교에 쓴 파일이 있다.

- `harness.mjs`: 세 엔진으로 첫 페이지를 그리고, 회전과 마지막 페이지 삭제 뒤 저장해 결과를 `out` 폴더에 쓴다. `npm install` 후 `node harness.mjs`로 실행한다.
- `make_samples.py`: 한글 미내장·임베디드·스캔본 샘플을 만든다. 실행하려면 `reportlab`, `Pillow`, LibreOffice, `pdftoppm`이 필요하다.
- `samples`: 위 스크립트로 만든 시험용 PDF 3종.

PDFium을 쓸 때 참고할 점은 다음과 같다. 저장은 `FPDF_SaveAsCopy`를 쓰고, 쓰기 구조체(8바이트: 버전과 콜백 포인터)는 `addFunction`으로 만든 콜백을 연결한다. 초기화 뒤에 `PDFiumExt_Init()`를 한 번 호출해야 한다.
