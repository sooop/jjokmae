# 쪽매 구현 계획

## 요약

Svelte 5 + Vite로 PDF 편집기 쪽매를 만든다. 같은 소스에서 세 가지 결과물을 빌드한다.

| 빌드 | 명령 | 결과 |
|---|---|---|
| 로컬 개발 서버 | `npm run dev` | Vite 서버 (HMR) |
| 정적 사이트 | `npm run build:static` | `dist-static/` (HTML+JS+WASM 파일 분리, 아무 정적 서버에 올림) |
| 단일 HTML | `npm run build:single` | `dist-single/index.html` (JS·워커 인라인, WASM·폰트는 CDN에서 내려받아 IndexedDB 저장) |

엔진은 PDFium·MuPDF 어댑터를 모두 만들고, 재측정 결과로 기본 엔진을 정한다(사용자 결정: 차이가 뚜렷하면 자동 결정).

## 확정된 결정

- 테마: 모노톤, 다크 모드 동시 지원
- 샘플: 합성 샘플 3종으로 측정. 서명 PDF는 직접 만들어 시험
- 기본 엔진: 측정 결과가 명확하면 자동 결정, 애매하면 사용자에게 질문
- 이전 장 "작업지시서.md"의 화면 규칙·저장 원칙을 그대로 따른다

## 빌드 타깃별 차이

- 정적 사이트는 WASM·폰트를 같은 출처 파일로 두고 `fetch`한다(IndexedDB 캐시는 같이 사용).
- 단일 HTML은 `vite-plugin-singlefile`로 JS·CSS·워커를 인라인하고, WASM·폰트는 버전 고정 CDN URL + 해시 검증 후 IndexedDB에 저장한다.
- 엔진 바이너리 공급 방식은 `BinarySource` 인터페이스 하나로 추상화하고, 빌드 상수(`__TARGET__`)로 구현을 고른다.

## 단계

1. **설정**: 프로젝트 뼈대, 세 빌드, 어댑터 인터페이스, `file://` 검증 (병렬 A)
2. **재측정**: 하네스 확장 — 한글 폰트 등록(PDFium), 주석·양식 저장, 서명 PDF 증분 저장, 브라우저 PDF.js 한글 (병렬 B)
3. **기본 엔진 결정**: 결과 표 → 문서화(`docs/엔진결정.md`)
4. **어댑터 구현**: PDFium, MuPDF, 같은 시험 PDF로 열기·그리기·회전·삭제·저장
5. **WASM 로더**: 다운로드·해시·IndexedDB·진행 표시
6. **뷰어·썸네일**: 가상 스크롤, 확대, 이동
7. **페이지 조작**: 재정렬·삭제·회전·병합·분할·추출
8. **주석·양식·서명**
9. **저장 옵션**: 증분, 평탄화, 객체 정리
10. **마무리 점검**: 성공 기준 확인, 미확인 항목 보고

1·2단계는 서로 간섭이 없어 병렬로 진행한다.
