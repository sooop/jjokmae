# 다중 문서 작업 공간 설계

## 요약

여러 PDF를 탭으로 동시에 열고, 한 문서에서 고른 쪽을 새 파일이나 다른 열린 파일로 복사·이동한다. 기존 "병합 대기 목록"은 없애고 열린 파일이 그 역할을 맡는다.

## 사용자 결정 (2026-11-12)

| 항목 | 결정 |
|---|---|
| 파일 전환 | 상단 탭 바 |
| 쪽 보내기 | 보내기 메뉴 + 탭으로 드래그, 둘 다 |
| 복사·이동 | 기본 복사, 메뉴에서 이동 선택 |
| 병합 대기 목록 | 없애고 여러 파일은 모두 탭으로 연다 |

## 동작

### 열기

- "파일 열기" 버튼과 Ctrl+O는 항상 새 탭으로 연다. 현재 문서를 닫지 않는다.
- 뷰어 어디에 놓아도 열린다. 여러 파일을 놓으면 모두 탭으로 열고 마지막 파일을 활성으로 한다.
- 같은 이름의 파일은 `이름 (2).pdf`처럼 구분한다.
- 열기에 실패한 파일은 탭을 만들지 않고, 파일명을 짚어 안내한다.

### 탭

- 탭마다 파일명, 변경됨 점, 닫기 버튼을 둔다. 넘치면 가로 스크롤한다.
- 탭별로 현재 쪽, 확대 배율, 선택 쪽, 되돌리기 기록을 따로 보관한다. 전환하면 보던 자리로 돌아온다.
- Ctrl+Tab, Ctrl+Shift+Tab으로 전환하고 Ctrl+W로 닫는다.
- 저장하지 않은 변경이 있는 탭을 닫으면 탭 근처에 확인 안내를 띄운다.

### 보내기

선택한 쪽(기존 Ctrl/Shift 다중 선택)을 보낸다. 대상은 다음과 같다.

- 새 파일: 선택 쪽만 든 새 탭을 만든다. 저장 전까지 변경됨 상태다.
- 열린 파일: 맨 앞, 맨 뒤, 특정 쪽 뒤 중에서 위치를 고른다.

방식은 복사와 이동 두 가지다. 기본은 복사다. 이동은 대상에 넣은 뒤 원본에서 삭제한다.

탭으로 드래그하면 그 파일 끝에 복사로 붙인다. 정확한 위치나 이동은 메뉴를 쓴다. 터치와 키보드는 메뉴만 쓴다.

### 열린 파일 병합

메뉴 "열린 파일 병합"에서 파일을 체크하고 순서를 정해 새 탭으로 만든다. 원본 탭은 그대로 둔다.

## 구조

- 작업 공간 저장소가 문서 목록과 활성 문서를 가진다. 문서마다 엔진 문서 ID, 사용한 엔진, 이름, 변경됨 여부, 되돌리기 기록, 현재 쪽, 확대, 선택을 가진다.
- 기존 `runOp()`와 `rebase()` 규칙은 문서 단위로 그대로 적용한다. 저장한 문서는 저장 결과 바이트로 갈아탄다.
- 엔진 인스턴스는 사용한 엔진마다 하나다. 같은 엔진의 문서끼리는 `importPages`로 바로 옮긴다.
- 서로 다른 엔진의 문서 사이에서는 선택 쪽을 임시 문서로 추출해 바이트로 넘기고 대상 엔진에서 연다.
- 같은 문서 안 복제는 기존처럼 조작 전 스냅샷을 임시로 열어서 한다(PDFium은 같은 문서끼리 `importPages`가 안 된다).
- 설정에서 엔진을 바꾸면 이미 열린 문서는 원래 엔진을 유지하고, 새로 여는 파일부터 새 엔진을 쓴다. 이 점은 지금과 같다.

## 되돌리기

- 되돌리기 기록은 문서마다 둔다.
- 복사는 대상 문서에만 기록한다. 대상 탭에서 Ctrl+Z를 누르면 취소된다.
- 이동은 두 문서에 같은 묶음 번호로 기록한다. 어느 쪽에서 되돌려도 두 문서가 함께 되돌아간다. 활성이 아닌 문서가 바뀌면 탭 근처에 알린다.
- 새 파일로 보내기를 되돌리면 새 탭을 닫는다.

## 회귀와 한계

- 병합 대기 목록 UI가 사라진다. 병합은 열린 파일 병합 메뉴로 대신한다.
- 열린 문서마다 바이트와 되돌리기 스냅샷이 메모리를 쓴다. 전체 상한을 두고, 넘으면 오래된 문서의 되돌리기 단계를 먼저 줄인다.
- 문서가 많으면 엔진 힙이 커진다. 열린 문서 수 상한(예: 12)과 경고를 둔다.
- 암호 PDF는 기존처럼 열 수 없다는 안내만 한다.

## 검증 계획

1. 3개 문서를 열고 전환한다. 문서마다 현재 쪽·확대·선택이 유지되는지 확인한다.
2. 문서 A의 쪽을 새 파일, 문서 B의 앞·뒤·특정 쪽 뒤로 복사한다. 저장한 PDF가 qpdf를 통과하고 쪽 순서가 맞는지 확인한다.
3. 이동 후 두 문서의 쪽 수가 맞고, 한 번의 되돌리기로 두 문서가 함께 복귀하는지 확인한다.
4. 탭으로 드래그해 끝에 붙는지 확인한다.
5. MuPDF 문서와 PDFium 문서 사이 전송이 되는지 확인한다.
6. 변경된 탭을 닫을 때 확인 안내가 뜨는지, 기존 페이지 조작·주석 시험이 그대로 통과하는지 확인한다.

## 정리 모드와 썸네일 크기 (2026-11-12 추가)

### 사용자 결정

| 항목 | 결정 |
|---|---|
| 탭 바 | 보기 모드에서만 표시. 정리 모드는 왼쪽 파일 목록이 대신한다 |
| 그리드 범위 | 파일 하나씩 표시. 파일을 바꿔도 파일별 선택은 유지한다 |
| 드래그 대상 | 왼쪽 파일 목록 항목에 놓기가 기본. 우클릭 메뉴로도 이동·복제를 할 수 있다 |

### 두 모드

- 보기 모드: 상단 탭 + 왼쪽 썸네일 + 본문. 지금 화면에 탭이 더해진다.
- 정리 모드: 왼쪽 파일 목록 + 오른쪽 썸네일 그리드. 본문은 없다.
- 두 모드는 같은 문서 목록과 같은 쪽 선택을 공유한다. 모드를 바꿔도 선택, 활성 문서, 되돌리기 기록이 유지된다.
- 정리 모드에서 쪽을 더블클릭하면 보기 모드로 바꾸고 그 쪽을 연다.
- 모드 전환은 툴바 버튼과 단축키(예: G)로 한다.

### 정리 모드 화면

- 왼쪽 파일 목록: 파일명, 쪽 수, 변경됨 점, 파일별 선택 쪽 수, 닫기 버튼. 맨 아래에 "새 파일" 칸이 있다.
- 오른쪽 그리드: 썸네일 격자. 쪽 번호를 표시하고 보이는 쪽만 그린다.
- 위쪽에 크기 슬라이더가 있다.
- 쪽 선택은 클릭, Ctrl 클릭, Shift 클릭, 드래그 영역 선택(빈 곳에서 끌기)을 지원한다.
- 그리드 안 재정렬은 기존처럼 드래그로 한다. 파일 경계를 넘는 이동은 하지 않고 파일 목록으로 보낸다.

### 쪽 보내기

- 선택 쪽을 왼쪽 파일 목록의 파일 위에 놓으면 그 파일 끝에 복사한다. "새 파일" 칸에 놓으면 새 파일이 만들어진다.
- 선택한 쪽이나 파일 항목에서 우클릭하면 메뉴가 뜬다: 복사, 이동 → (새 파일 / 열린 파일 목록 / 위치 선택), 복제, 회전, 삭제, 추출, 분할.
- 여러 파일에서 고른 쪽 모두를 한 번에 보내려면 "선택한 쪽 모두 → 새 파일"을 쓴다. 파일 순서대로, 파일 안에서는 쪽 순서대로 합친다.

### 썸네일 크기

- 정리 모드 그리드: 슬라이더로 연속 조절한다(약 80~320px). 마지막 값을 설정에 저장한다.
- 보기 모드 왼쪽 썸네일 패널: 같은 방식으로 폭을 조절한다(약 100~280px). 패널 폭을 끌어서 바꾸는 방법과 설정 서랍의 크기 선택을 함께 제공한다.
- 크기가 바뀌면 렌더 배율도 바뀐다. 크기를 줄일 때는 이미 그린 비트맵을 쓰고, 늘릴 때만 다시 그린다. 연속 조절 중에는 CSS 배율로 먼저 보여 주고 멈춘 뒤 다시 그린다.

### 회귀와 한계

- 정리 모드에는 본문 뷰어가 없어 주석·양식 편집은 보기 모드에서 한다.
- 파일이 하나뿐이어도 정리 모드는 쓸 수 있다. 목록에는 파일 하나만 보인다.
- 큰 그리드는 보이는 쪽만 그려야 한다. 300쪽 문서를 최소 크기로 두면 한 화면에 수십 쪽이 보이므로 동시 렌더 수 상한을 유지한다.

### 구현 단계

1. 작업 공간 저장소, 상단 탭, 추가 열기, 보내기 메뉴, 열린 파일 병합, 이동 묶음 되돌리기
2. 정리 모드(파일 목록, 그리드, 선택, 드래그, 우클릭 메뉴)와 썸네일 크기 조절
