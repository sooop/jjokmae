# 기본 엔진 결정: MuPDF

결정일: 2026-11-11. 근거 데이터: `harness/결과.md`, `harness/out2/` (합성 샘플 기준, Node 환경).

## 결정

기본 엔진은 MuPDF로 한다. PDFium 어댑터도 만들어 설정에서 바꿀 수 있게 둔다.

## 근거

| 항목 | MuPDF | PDFium |
|---|---|---|
| 한글 폰트 미내장 문서 렌더링 | 설정 없이 정상 | 한글 폰트 10~13MB를 등록해야 보임 |
| 한글 FreeText 주석 | 보임 | 폰트를 등록해도 박스만 그려짐 |
| 한글 양식 값 | MuPDF·PDF.js에서 보임 | 저장본 대부분에서 안 보임 |
| 영문 주석 4종 저장·재로드 | 통과 | 통과 (AP 생성 함수를 직접 호출해야 함) |
| 양식 렌더링 | 기본 렌더로 위젯 표시 | 폼 환경과 `FPDF_FFLDraw` 필요 |
| 증분 저장 | 서명 ByteRange 유지, 원본 접두 보존 | 같음 |
| 전체 저장 | 서명이 깨짐 | 같음 |
| 삭제 쪽 객체 정리 | `garbage=compact` 필요 | 기본 저장으로 정리됨 |
| WASM 외부 주입 | 가능 (`globalThis.$libmupdf_wasm_Module`, import 전에 설정) | 가능 (`init({ wasmBinary })`) |
| 라이선스 | AGPL-3.0 (개인용이라 문제없음) | MIT / Apache-2.0 |
| WASM 크기 | 10.4MB | 4.6MB |

## 결정이 뒤집힐 수 있는 조건

- 사용자의 실제 한글 PDF에서 MuPDF 렌더링이 문제를 보이는 경우
- 증분 저장 뒤 Acrobat이 서명 경고를 내는 경우 (미확인)
- 배포 계획이 생겨 AGPL이 문제가 되는 경우

## 확인하지 못한 것

- Acrobat·브라우저 기본 뷰어에서 주석 재편집과 서명 상태
- 한글 시스템 폰트가 없는 환경의 PDF.js 렌더링
- `file://`에서 PDFium 폰트 훅 (MuPDF WASM 주입은 단일 HTML 시험으로 확인함)
- 실제 사용자 PDF
- 엔진 간 성능 비교 (번들 크기는 빌드로 확인함: 단일 HTML 약 590KB, WASM은 별도)
- 서명 PDF의 증분 저장: 서명 해시는 유지되지만 주석 추가·회전은 pyHanko가 `ILLEGAL_MODIFICATIONS`로 분류한다 (두 엔진 공통, `마무리점검.md` 참고)

## 구현 지침

- MuPDF 저장은 삭제가 있으면 `garbage=compact`를 쓴다 (`garbage=yes`는 이 버전에서 오류).
- MuPDF WASM은 `globalThis.$libmupdf_wasm_Module = { wasmBinary }`를 import 전에 설정한다.
- 주석은 `annot.update()`로 AP를 만든다. MuPDF의 Text 주석은 Popup을 함께 만들므로 목록 표시 때 Popup은 숨긴다.
